01 / FRAMEWORK 原文稿转述 + 编辑边界说明

三阶段是价值链坐标，不是交棒时刻表

文稿将这一轮变化概括为“基础设施 → Agent 应用 → 能力分发 / 操作系统”。这里的箭头表示观察重心的移动，不表示前一阶段结束后，后一阶段才会出现。[P0 · 文稿来源边界]

01

基础设施：把能力造出来

观察算力、模型、机房和交付容量。分析重点是前置投入多久才能转成被使用、被付费的服务，而非采购了多少设备。对独立开发者，真正接触到的往往是调用价格、可用性和延迟，不是整座数据中心的账面规模。

02

Agent 应用：把任务做完

本文把 Agent 理解为能够组织多步工作、调用工具并处理状态的任务系统。一个演示能运行，不等于客户能放心交付；任务验收、失败恢复、权限边界和人工复核，决定它是在生成内容，还是在承担工作流程。

03

能力分发：决定谁被调用

此处“操作系统”是功能类比：管理身份、上下文、工具发现、任务路由与结算。它不必是新的桌面系统，也可能依附搜索、设备或工作环境。掌握入口和拥有全部底层算力，是两个不同问题。

补充推论 三层可以同时竞争，也可以由同一家公司跨层经营。应用可能把模型替换成更便宜的供应商，入口可能调用外部云，基础设施商也可能直接提供开发工具。因此，“模型更强”与“应用没有价值”、“有设备入口”与“无需外购算力”，都不是逻辑等价式。Apple 的 PCC 扩展公告正好提供了后一种区分的实例。[S04 · Apple · 2026-06-08]

历史类比可以提出问题，不能代替预测模型

以下只保留原文稿中的 SGI、电信、铁路类比作为假设工具；没有在此重建这些行业的历史财务序列，也没有推出任何公司将重复其结局。[P0]

SGI 类比：优势会不会迁移？

把它当作“专业计算平台的优势是否会被新的技术组织方式改写”的问题。需要检验的是替代方案的性能、迁移成本和开发者生态，而不是因为同样销售计算能力，就预设 NVIDIA 的命运。

电信类比：容量是否先于需求？

它提醒我们拆开建成容量与付费利用率。但不同地区、网络条件、芯片代际和工作负载未必能互相替代；一处闲置，不能证明全行业过剩，一处排队，也不能证明所有项目都值得继续扩张。

铁路类比：使用价值归谁？

它让人区分社会使用价值与建设者的经济回报。即使基础设施帮助大量下游业务，也不能跳过融资、定价和债务期限的分析。受益者与出资者可能不同，但这里不预测它们必然分离。

为什么不能把三个类比拼成“泡沫必然破裂”？

类比只抽取了相似机制，没有提供相同的初始条件。有效的比较至少要说明资产寿命、需求弹性、竞争结构、融资成本和供给可迁移性；缺少这些变量，历史故事可以支持多种相反叙事。本文因此不设置周期拐点年份，也不推导某家公司必胜或必败。

同样，基础设施存在盈利企业，并不意味着每个新增项目都具有相同回报。正确的分析单位应下沉到项目、客户与工作负载，而不是把整个行业压缩成一个情绪标签。

02 / CLAIM AUDIT 九项核对 · 不替代原话校勘

先修正九个容易滑向结论的命题

下列“原观点 / 待核命题”根据所给文稿及勘误要求整理，不是对原话的逐字引用，亦未经原音频校勘。事实判断、概念纠正和证据不足分别处理；判为证据不足，不等于已经证明相反命题。[P0]

01时间线：1990年代的固定互联网，不是移动互联网
原观点 / 待核命题

在历史阶段的讲述中，把1990 年代光纤铺设所服务的固定互联网称为移动互联网。

概念纠正

本页统一改为“1990年代的固定互联网 / 早期 Web”。不能把固定接入、移动设备入口和今天的 AI 任务入口当成同一种分发条件；这里纠正术语，不额外宣称某个唯一的移动互联网起始年。校对依据为本次提供的时间线勘误要求。[P0 · 勘误范围]

02历史类比：机制假设，不是公司命运预告
原观点 / 文稿转述

借 SGI、电信建设和铁路投资理解 AI 基础设施与平台迁移。

保留类比，撤去必然性

需要证明的是需求兑现、供给替代、融资压力等机制是否相似，而不是先给出同样结局。本文把这些比喻保留为可检验问题，不把它们写成市场预测、投资回报预测或破产预告。[本文 §01 · 类比边界]

03计量单位：token 不是跨模型统一的“智能吨位”
原观点 / 待核命题

用 token 数量或每百万 token 单价，直接比较不同模型的产能、能力和经济价值。

计量纠正

分词方式、语言、输入与输出类别都会影响计量；同一任务也可能产生不同长度的推理和结果。应固定任务、质量门槛与延迟要求，比较验收成功的总成本；不能把低 token 单价直接等同低交付成本。[M01 · OpenAI 计量说明]

04成本：数字服务不等于边际成本为零
原观点 / 待核命题

模型训练完以后，新增用户或新增回答不再产生成本。

否定绝对说法

新增推理、工具调用、重试和服务支持都可能增加费用；容量扩张还可能带来阶梯式成本。微软对 AI 投入与云毛利的解释提供了成本压力的背景，但不能据此反推任何一条回答的成本。[S02 · 2026-07-29][M01 · 调用计量]

05付费：消费者“永远不付钱”是错误命题
原观点 / 待核命题

消费者产品只能免费，只有企业客户愿意付费。

存在反例，不泛化支付意愿

微软披露的消费者订阅业务及订阅量增长，足以否定“消费者从不付费”。但这也不能证明任意 AI 工具都能收费。应按任务频率、可替代性、节省时间与个人预算区分需求，而不是用 C 端 / B 端标签代替用户研究。[S02 · 消费者订阅披露]

06商业模式：广告出现，不等于订阅失败
原观点 / 待核命题

广告与付费只能二选一；引入广告便说明用户不愿订阅，或者广告已经左右答案。

证据只支持广告业务存在

OpenAI 的公告支持其广告平台与相关产品的存在，不能证明订阅模式失败，也不能证明广告影响独立回答。免费用户、付费高价值层与广告可以共存；实际答案独立性仍需独立验证，不能只凭厂商承诺判定。[S07 · 2026-09-16]

07Google 动机：“故意稀释搜索”没有充分证据
原观点 / 待核命题

搜索产品改变，就意味着 Google 有意降低搜索价值或主动牺牲现有业务。

不支持动机归因

产品发布能证明产品变化，不能单独证明内部战略意图。防守用户意图、改善体验、寻找新变现与降低流失，都是可能解释。miniapps 在所引公告中仍是未来计划，本页不把计划升级为已核实上线。[S05 · 2026-05-19]

08财务口径：单季、年化与全年实际不能互换
原观点 / 待核命题

Google 每年广告收入约4,000亿美元；单季收入乘四即为全年收入；不同公司的资本支出可以不校准周期就比较。

改用同期间、同定义的数据

Google 2025 全年广告收入为 2946.91 亿美元；这是全年实际口径。2026 Q2 广告收入为 816.29 亿美元，季度乘四仍只是算术年化，不能充当全年实际。详见 年度财报核验补充。广告合计与纯搜索收入、收入与利润应分别标注。

09巴菲特 / 喜诗类比：保留讲话归属，不制造引语
原观点 / 文稿转述

原讲话借巴菲特与喜诗糖果（See’s）的故事讨论商业质量。

解释有边界，出处仍待核
03 / GOOGLE 上半部唯一展开对象

Google：争夺的可能是“任务从哪里开始”

原文稿转述 Google 的观察主线是“用户意图”。本页将它拆成入口防守、变现、推理成本与云业务四个问题；这些展开属于编辑分析，不冒充讲话逐字内容。[P0]

先确定公开材料真正说了什么

产品公告 Google 于2026年5月19日介绍 Search agents，并宣布 AI Mode 使用 Gemini 3.5 Flash；同文中的 miniapps 属于未来计划。本文没有用后续上线证据替换这一状态。[S05 · 2026-05-19]

财务披露 S09 的 Google advertising 是广告合计，不能当作纯搜索广告收入。收入数字描述已经发生的经营结果，不说明管理层希望主动缩小哪一项业务。[S09 · 2026-07-22]

推论 A防守意图：让用户先在自己的界面描述任务

当查询从几个关键词变成一段目标、约束和上下文，入口可能更早接触到用户的决策过程。由此可以推测，搜索代理有助于维持 Google 与任务发起者的关系；但同一产品变化也可能只是为了减少来回搜索的步骤，不能从结果倒推唯一动机。[依据 S05；动机为本文推论]

如何检验：比较同类任务的完成率、再次使用率、外部访问与最终转化。即使查询次数增加，也需要判断新增的是有效需求、任务拆分，还是反复追问；一个总量指标无法回答入口价值是否提高。

推论 B重组变现：从页面曝光转向不同价值的任务

一种分析路径是把商业价值拆为任务量、商业意图占比、转化质量与单位变现。回答更完整，可能减少某些点击，也可能让部分商业需求表达得更清楚；净影响必须依靠分组数据验证。不能把所有查询视为同等价值，也不能把单季广告增长全部归因于 AI。[S05][S09；因果未识别]

边界：这不是“Google 故意稀释搜索”的证据。为了改善体验接受某些旧指标下降，与有意破坏业务价值，是两个不同命题。需要观察的是用户价值和收入结构如何共同变化。

推论 C控制推理成本：更好的答案仍要经过账单检验

多轮推理、检索和工具执行可能改变一次任务的资源消耗。评价新入口，需要同时考虑成功交付数、平均成本和高成本尾部。路由、缓存与简化流程可以作为小团队的工程试验方向，但不能据此声称已经知道 Google 的单次 AI 搜索成本。[M01 · 任务计量依据]

证据缺口：本页引用的 Google 材料没有提供可直接计算单次 AI 搜索利润的完整数据。微软关于云毛利压力与效率改善的披露只能作为跨公司背景，不能替 Google 填入成本参数。[S02 · 背景而非代理测量]

推论 D云业务分散变现路径，但不会自动分散所有风险

Apple 宣布把 PCC 扩展至采用 NVIDIA 的 Google Cloud，为“入口在别处，计算服务仍可由云平台提供”给出了公开实例。由此可以推测，Google 不只可能从自身搜索入口获得商业机会，也可能服务别人的入口。[S04 · 2026-06-08；后句为推论]

这种多路径变现可能降低对单一产品形态的依赖，但客户集中、长期采购承诺和基础设施成本也可能产生新的相关风险。它不是已证实的内部战略意图，更不能证明云收入一定能抵消任何搜索业务变化。

对创作者：把“被看见”和“建立关系”分开计量

一个可执行的做法，是分别记录内容被引用、用户到站、订阅和成交，而不是把摘要中的一次提及等同一个客户。把重要事实写清、给出可追溯出处、明确内容授权与联系路径，是可控的编辑工作；这并不承诺获得任何平台的排序优待。对开发者，则应保存用户授权的任务记录、验收标准与可导出的项目状态，让产品价值不依赖某一模型名称。

05 / INFRASTRUCTURE 本页独立补充分析

基础设施周期：采购金额只是第一站

观察资本开支时，先把链条拉长：签约、交付、通电、部署、被使用，再到回款。任何一环延迟，都可能使资本投入和收入确认错位；这是一套项目分析框架，不是对全行业利用率的测量。

  1. 01 采购 / 融资
  2. 02 交付 / 通电
  3. 03 部署 / 使用
  4. 04 计费 / 回款

利用率与利息负担，要放在同一张工作表

利用率应区分设备在线、正在计算与有效付费工作负载。即便机房很忙，也可能存在低价试用、低效率任务或内部需求；因此不能只用“忙碌程度”推算现金回收。

对有融资的项目，还应检查利率、到期日、最低采购承诺和还款节奏。折旧是成本分摊，利息是融资代价，资本支出是资产投入；三者不能混用。本文不假定任何一家公司的新增项目一定依赖高负债。

电力与网络约束，会造成局部供需错配

情景分析不能假设“买到芯片”就等于“立即可交付计算”。供电、冷却、网络互联和数据位置都可能改变部署时间。这里列的是应检查的约束，并非声称这些约束已经同时发生在每家公司。

同样，训练与推理、不同芯片代际、不同延迟等级未必共享一张完全可替换的供给池。短缺与闲置可以在不同位置并存。要否定或支持“过度建设”，需要分地区、分代际、分负载的利用率和合同数据。

并列记录，不做横比 Meta 的2026全年资本支出指引为130–145十亿美元，第二季度资本支出为31.08十亿美元，这两个资本支出口径均包含融资租赁本金；该季营业利润率31%。微软上述数据是一个财季，不能用41与130–145直接比较投资力度。[S01 · 2026-07-29][S02 · 同日发布]

利润率也要保留分母 微软该季 Microsoft Cloud 毛利率为65%；公司解释 AI 投入等因素带来压力，效率改善部分抵消。NVIDIA 单季 GAAP 毛利率见 S08；它不是云服务商毛利率，更不是应用开发者能获得的利润率。[S02][S08]

分析结论的边界：本资料包没有足够的项目级利用率、能源接入成本、债务期限和回款数据，不能据此判定全行业一定过剩或一定短缺。对小团队更直接的动作，是控制固定承诺，记录真实服务成本，而不是将巨头资本支出变成自己的需求预测。

06 / PRICING 本页独立补充分析

订阅、广告、按量与混合，不是单选题

以下比较是定价设计框架，不引用任何厂商的实时套餐价格。应先问谁获得价值、谁承担账单、成本随什么增长，再决定收费方式；不能从某家公司新增一种收入来源，推导另一种模式已经失效。[广告存在的实例：S07 · 2026-09-16]

01 / 订阅

适合检验：稳定、重复、价值可预期的任务。用户买的是可持续获得的服务，而不必理解底层每次调用。

主要张力：收入较固定，重度用户的服务成本可能快速增加。应清楚说明额度、速度或人工服务范围，避免用无法兑现的“无限”掩盖约束。

02 / 广告

适合检验：存在可识别商业需求，并且广告主愿意为可验证的触达或转化付费的场景。

主要张力：付款者与使用者不同。应清楚区分赞助内容和独立答案，并检验广告负担对体验的影响；不能默认任何免费流量都能覆盖服务成本。

03 / 按量

适合检验：任务量波动大，且用户能够理解和控制使用规模的服务。计费单位可以是调用、任务或约定成果。

主要张力：成本更易对应，但账单不确定性会增加使用顾虑。预算上限、失败计费规则和可解释的用量记录，比单纯展示 token 数更贴近用户决策。

04 / 混合

适合检验：免费入门、高价值付费层、基础订阅与超额按量的组合；在适当场景也可并存明确标识的广告。

主要张力：分层过多会使价值难以理解。免费层必须进入成本表，付费层必须说明增益，广告也不能被偷偷当作“零成本补贴”。

编辑判断 判断支付意愿，要回到具体任务。高频、可验证、能减少返工的功能可以设计付费实验；低频探索性功能也可能更适合免费试用或按次收费。无论采用哪种方式，都应以用户实际选择和留存检验，而不是把企业愿付费、消费者只要免费当作先验结论。

把“很受欢迎”翻译成一张月度成本表

这是一个假设中的创作者工具：付费用户购买月度服务，免费任务也消耗 API。月份固定为2026年10月，货币全部为美元（USD）；输入不是任何公司的真实价格、用户数或经营数据，结果也不构成市场规模预测。

编辑假设后，按“重新计算”更新下方结果

当前显示默认示例。禁用脚本时，输入不可编辑，完整公式与结果仍可阅读。

2026年10月 · 简化月度试算

月收入 USD 2,000.00
列示费用合计 USD 1,580.00
简化月度余额 USD 420.00

本月任务数：10,000 次，包含免费层；不是验收成功任务数。余额 / 收入：21.0%，不是会计毛利率或净利率。

公式、口径与默认示例的人工复核
任务数 = 付费用户 × 每人任务数 + 免费任务数
收入 = 付费用户 × 月费
基础 API = 任务数 × 首次执行 API 成本
额外重试 = 基础 API × 重试费用比例
月度余额 = 收入 − 基础 API − 额外重试 − 托管 − 支持服务 − 当月获客

按默认假设：100 × 80 + 2,000 = 10,000次任务；2,000 − 800 − 160 − 120 − 200 − 300 = 420美元。各项金额按美分四舍五入后求和。该静态复核仅针对默认值，不随输入变化。

同一默认示例中，若首次执行 API 成本单独翻倍为0.16美元，重试费用比例仍为20%，其他输入不变，则月度余额为−540美元。这是数学敏感性分析，不预测任何 API 价格会上涨。

未计入未填写的创始人工时、研发、税费、支付手续费、退款、折旧、资本支出与融资成本，也未建模流失和跨月回收。真实经营应补齐这些项目；本余额不能被称为完整利润。没有广告收入假设，不代表广告模式不可行。

08 / FIELD NOTES 编辑工作清单 · 非投资建议

给创业者的五个观察，给研究者的五个指标

创业者：五个实际观察

  1. 从可验收的小任务开始，而不是从通用助手开始

    先写清“完成”意味着什么。例如，创作者的资料核对工具可以要求每条关键事实有出处、日期与人工确认；开发工具可以要求修改通过测试并可回滚。把输入、交付物和失败条件写下来，才能判断模型变强是否真的改善产品。

  2. 比较成功交付成本，不比较抽象 token 单价

    为同一批代表性任务记录首次执行、重试、人工复核与等待时间。保留失败样本，避免只比较最顺利的演示；低调用价格若伴随更多返工，未必更便宜。这个试验应控制任务质量，而不是只控制输出字数。[M01 · 计量边界]

  3. 把用户关系与模型供应商分开设计

    在适用授权下支持数据导出、任务记录迁移和模型替换。真正值得积累的是用户的工作流程、偏好确认与验收反馈，而不是锁死在一个接口上的提示词。替换也有测试成本，因此应记录切换代价，不必为了多模型而制造复杂系统。

  4. 免费层也进入成本表，付费层要有明确增益

    免费体验可以用于降低尝试门槛，但应计算其服务与支持消耗。给付费层提供可解释的价值，例如更多可验收任务、更完整历史或明确的服务范围；避免把“无限使用”当作替代成本管理的营销口号。不同收费模式可以小范围检验，不必一次押注全部收入来源。

  5. 把可信交付做成流程，而不是一句承诺

    让客户能查看来源、确认敏感操作、撤回权限，并在失败时恢复工作。企业合作公告可以帮助识别需求方向，但仍要验证实际使用与净收益；不要把采购、试点和持续使用混成一个“客户数”。[S06 · 企业公告与回报的区别]

行业研究：五个应持续跟踪的指标组

01 / 供给兑现率：从交付到有效付费使用
分别记录合同容量、已部署容量和有效付费容量，说明地区、芯片代际与工作负载；同时跟踪通电与网络交付的时间差。若定义不同，就不合并为一个行业利用率。本资料包未提供完整测量值。
02 / 现金与期限：投入能否等到回款
校准财季、自然年、现金购置设备与融资租赁口径，再观察现金回收、利息和承诺期限。微软与 Meta 的支出应按各自披露定义保存，而不是为了排行强行统一。[S02][S01]
03 / 任务经济性：质量约束下的全成本
跟踪成功率、端到端延迟、重试、人工复核与每次验收成本的分布。既看中位数，也看最昂贵的一批任务；不要将本文假设计算器的余额率与上市公司披露的毛利率放在同一张比较表。
04 / 采用质量：从签约到持续使用
区分宣布合作、采购额度、激活用户、持续使用和续约。企业部署公告是起点，不是净投资回报的终点；不同收入期数不能混用，季度收入年化也不等于已实现全年收入。[S06][S03]
05 / 分发与信任：入口变化之后，关系留在哪里
记录任务发起、完成、到站与付费之间的转化，同时观察引用可追溯性、广告标识和用户授权。Google 的产品变化与 OpenAI 的广告公告是观察线索，不是答案质量、独立性或所有创作者流量变化的直接测量。[S05][S07]
