01 / YOUR QUESTION

为什么发布 Sol 6.1，却没有 Astra 6.1？

目前最有依据的回答：Astra 6.1 的公开发布被安全门槛挡住；Astra 产品线仍在扩展。

直接读到的 CBS 报道援引 OpenAI 安全负责人：新版在授权范围和工作汇报方面未达要求。[B1] 大会官方则确认现有 Astra 的 Ultrafast 和 Dots 应用。[A1]

B · 转述公司声明

发布受阻的具体含义

边界：没有拿到 Astra 6.1 的公开评估表、新发布日期或完整官方声明；不将“本次不发布”写成“永久取消”。

C · 研究分析

Sol 上线与 Astra 缺席并不矛盾

两个模型的训练、评估与发布门槛可以不同。Sol 6.1 通过了自己的发布流程，不能据此推导 Astra 6.1 也已可发布；更不能把安全问题直接等同于“能力太强所以被禁”。

反证：若后续正式系统卡或 OpenAI 澄清给出不同原因，应修订此判断。成本与市场竞争解释了 Sol 的定位，不能单独解释 Astra 6.1 被撤下。

C · 分析

Ultrafast：Astra 更新了速度，未换成 Astra 6.1

A · 官方速度文档

Codex 中 Astra Ultrafast 的 token 生成速度最高约为 Standard 的 8 倍；套餐内额度也按 Standard 的 8 倍消耗。购入 credits 与企业按量计费为 6 倍费率。[A6]

Sol 6.1 当前支持 Standard / Fast；Ultrafast 尚待推出。[A2]

C · 条件计算

假设一项任务 25% 的时间花在模型生成、75% 花在工具和等待，即使生成提速 8 倍，总提速也只有 1 ÷ (0.75 + 0.25 ÷ 8) ≈ 1.28 倍。

升级是否划算，要量“从派任务到验收”的时间；不能拿 token/秒当整个项目提速。仅在减少的等待确实有价值时用加速档。

模型降价，与会员用量缩减同时发生

官方可确认的套餐变化

Pro 500$500包含

Pro 500 为 Plus 用量的 25 倍；符合资格的既有 Pro 200 旧额度保留至 2026-10-29，随后降低。保留旧额度并不获得 Pro 500 权益。[A7] [A1]

三种账不能混算

  1. API：按 token、工具和速度档位计算。
  2. 订阅：按套餐额度、模型和使用模式计量。
  3. 伙伴应用：获授权后可用共享套餐额度，仍受限额和应用权限控制。

第三方登录不意味着开发者可无限使用用户额度；仅退出伙伴应用也不等于断开授权。[A8]

C · 分析“按 AI 员工收费”是中文作者的商业比喻。公开 API 仍按 token 等计费；订阅也不是纯粹“只有验收成功才付费”的结果定价。更准确的趋势是：平台正在把模型能力、工作量、速度与分发分别定价。[N1]

05 / RESEARCH & IMPLICATIONS

大会主线：从提供模型，走向组织工作

C · 推断

① 成本下降扩大代理任务

Sol 的经济性可能让此前只适合高价值任务的流程，扩展到更多日常交付。关键是能否稳定得到合格结果，而非多生成内容。

验证：同一批真实任务测通过率、成本、重试与人工分钟。

C · 推断

② 持续上下文形成黏性

代理积累偏好、权限和反馈后，替换成本可能上升。它既能减少重复交代，也可能增加对单个平台的依赖。

反证：若用户仍频繁重新解释任务，或迁移上下文很容易，该壁垒会弱于预期。

C · 推断

③ 分发成为第二战场

官方以合计 12 亿周活用户描述分发面，插件入口、登录和企业采购连接了用户、工具与预算。[A1] 但平台规模不能自动转换成单个开发者的获客。

验证：曝光→安装→完成首个任务→付费→复用，逐层看漏斗。

Dots 真正改变什么？

官方描述 Dots 拥有独立云电脑、由 Astra 驱动、通过插件连接应用，用户可用规则控制行动。后台主动研究采用只读工具。[A9] 分析：因此，“全天在线”不等于“可以在无人审核时做所有外部写入”。真正的新能力是持续收集上下文、推进已授权任务并把可审查成果带回来。

对三类使用者的建议

对象优先试验合格证据容易失败的地方
创作者一个访谈→带来源的文章草稿、摘要与发布材料原意和引用无误；人工修订时间下降；读者反馈可追踪“文风像我”掩盖事实变化；多平台稿件重复返工

D · 建议

先做一周对照，再决定订阅或迁移。选 10–20 个近期真实任务，固定材料、验收标准和工具条件，对比 Sol 6.1 / Astra 的质量、总时长与成本。Ultrafast 单独测；不要同时换模型、工作方式和全部工具，否则无法知道哪项变化有效。

未来最值得研究的五个问题

  1. Astra 6.1：是否公布修复后的评估及新的发布安排？关键看授权与报告透明性。
  2. Dots：在连续一周真实任务中，主动建议有多少被接受？误报与漏报各是多少？
  3. 云端 Codex：本地依赖、私有网络和专业软件的任务能否完成？云上可用并不代表本地方式退出。
  4. 平台分发：插件推荐带来的是有效用户还是一次性尝鲜？可否导出客户与工作成果？
  5. 成本边界：共享额度和速度档能否让用户提前预测账单，而不是事后才发现额度耗尽？
