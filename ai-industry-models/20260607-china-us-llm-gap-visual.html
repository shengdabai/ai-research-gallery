01核心判断：不是「一代差」，而是「场景分裂」

总体可压缩成一句话：中国模型在 base / open model 层已经很强；美国/西方在闭源前沿、产品化 RL、agent harness、企业部署闭环上仍强。

🇨🇳 中国模型已接近 / 局部领先

  • 开源权重 & 本地部署生态
  • 中文语境（对话、文档、OCR）
  • 成本效率 / 每 token 成本
  • 部分 OCR / 文档理解
  • 短视频生成 & 创作素材
  • 小模型 / 边缘模型可用智能下沉
VS

🇺🇸 美国/西方仍有明显实用优势

  • 高稳定性长程 agentic coding
  • 复杂工具调用 & 多工具循环
  • 企业级低故障率 / 可审计闭环
  • 多模态 GUI / 浏览器自动化
  • 全球信任、合规与采购生态
  • 从模型到产品的 RL 闭环

03真正的代差：是稳定性，不是聪明度

很多讨论把问题说成「谁更聪明」，但真实用户反馈不是这样。中国模型在单轮问题、短程编码、局部任务、中文材料、私有部署中非常强——任务一旦变成长程，差距就出来了。

✅ 中国模型已经很强的场景

单轮问题 · 短程编码 · 局部任务 · 中文材料 · 私有部署。Qwen、DeepSeek、Kimi、GLM 在这些场景非常能打。

⚠️ 差距暴露的长程场景

跨文件修改 · 工具链循环 · 上下文压缩 · 反复测试 · GUI 操作 · 多小时 agent 任务。这些场景里用户对 Claude / GPT / Gemini 的「少出意外」仍更信任。

本地 Qwen 约有 Claude 工作流「95% 好」，但更啰嗦、更蛮干，需要更明确的完成定义。— Qwen3.6 用户 · Reddit / LocalLLaMA
复杂 agentic 任务中「definitely no Claude Sonnet 4.6」。— 同社区另一位用户的反向评价

核心差距：中国模型不是不聪明，而是在复杂真实工作流里，还不够稳定。那最后的 10%，决定能不能放心把任务交给它。

05小模型：中国已经非常强

小模型 ＝ 通常 <30–40B 激活参数，或可在单卡 / 消费级多卡 / Mac 统一内存上部署的蒸馏、MoE、边缘模型。用户选它不是因为「最聪明」，而是四个字：可控、便宜、够用。

🇨🇳 中国阵营

Qwen3 0.6B→235B（dense+MoE 全覆盖）、Qwen3-30B-A3B、Qwen3.6-27B/35B-A3B、DeepSeek R1 distill、GLM 小模型

🇺🇸 西方阵营

07工具链问题，本身就是实用代差的一部分

很多时候差距不只是模型本身，而是 parser、streaming、chat template、量化版本带来的工具调用错误。

✂️

Streaming 截断

vLLM issue：Qwen3 streaming tool call 把 50306 截成 503。

🔌

Parser 不兼容

Qwen2.5-Coder 生成了正确 XML 工具调用，但 parser 没填入 OpenAI 兼容的 tool_calls 数组。

🔁

Doom Loop

Qwen3.6-35B GGUF：UD-Q6/Q8 工具调用失败、输出不稳定、死循环，chat template 修复后改善。

这正是「实用代差」的核心：benchmark 里模型可能很聪明，但生产里一次 parser bug、一次 context compaction、一次错误工具调用，就会让用户回到 Claude / GPT。

08多模态：中国最强的是 OCR 和文档，不是万能视觉 agent

Qwen2.5-VL 强调文档/图表/视觉 agent；DeepSeek-VL2 用 MoE VLM + 动态 tiling + MLA KV 压缩覆盖 VQA/OCR/文档/表格；GLM-4.5V/5V 强调图像/视频/文档/GUI 操作。

✅ OCR / 文档抽取：接近或局部领先

1000 份文档 JSON 抽取评估：Qwen2.5-VL 72B/32B 约 75% 准确率，接近 GPT-4o，超过 Mistral OCR 与 Gemma-3 27B；32B 与 72B 接近、性价比更高。

Qwen3-VL-30B 在 3060 上约 20 秒/图，识别手机照片库存/配方并输出结构化数据。

⚠️ GUI agent：明显落后

Qwen2.5-VL 7B 做 UI 自动化：能描述屏幕、输出 UI 元素 JSON 坐标，但 agent 进入 endless loop；坐标接近但不准确，Ollama 图像 resize 影响效果。

手写 OCR 对 prompt/设置敏感，会漏段落、字母级准确率不稳定，暂不能无人工校验长期使用。

10四种常见叙事，逐条校验

点击展开每条叙事的真实性检验。

部分正确A · 中国模型已经 good enough 了↓⌄

对中文对话、学习、摘要、低成本 API、本地部署、小型 coding 辅助、OCR 抽取、短视频，确实足够好——很多用户会因免费/便宜/隐私/中文体验切换。

但不能泛化：对复杂工程、长程 agent、跨工具工作流，「good enough」常变成「还差最后 10%」，而那 10% 决定能不能放心交给它。有用户说 DeepSeek 免费但经常 server busy，仍为 ChatGPT 付费，因为一致性更重要。

只在开源里近似成立B · 中国模型已经全球采用领先↓⌄

HF 下载、OpenRouter token、Qwen/DeepSeek 派生模型数量，确实显示中国开放模型影响力巨大。

但消费产品上 ChatGPT 仍巨大领先；中国国内则是豆包、DeepSeek、Qwen、Kimi、元宝自成生态，不能直接等同于全球领先。

不够C · benchmark 已经说明中国追上了↓⌄

Benchmark 不能捕捉 compaction 丢信息、parser 出错、chat template bug、量化引发的 tool call 失败、长程任务自我纠错。

Cursor 对 Composer 2/2.5 的技术报告反而说明真正差距：不是只继续预训练 Kimi K2.5，而是用真实 Cursor 环境、长程任务、大规模 RL、synthetic tasks、behavior shaping 提升 end-to-end agent。这正是「裸模型很强、产品稳定性差一截」的根源。

也不准确D · 中国仍落后一整代↓⌄

Cursor 官方披露 Composer 2 / 2.5 都建立在 Kimi K2.5 开源基座上继续预训练和 RL。如果一个美国头部 coding IDE 的前沿 coding 模型可以建在中国开源基座上，就不能说中国还停在上一代。

更准确的是：中国在 base/open model 层已经很强；美国/西方在闭源前沿、产品化 RL、agent harness、企业部署闭环上仍强。

11差距为什么存在，又为什么在缩小？

四股力量同时作用：技术路线在收敛，数据结构不同，生态位置不同，芯片/监管/信任仍是外部变量。

① 技术路线在收敛

DeepSeek-V3 的 MLA、DeepSeekMoE、FP8 训练、MTP、低成本叙事 + Qwen/Kimi/GLM 的 MoE 化，都在算力受限下追求「每 token 成本」与「每激活参数智能」。这条路线极适合开放模型扩散：模型可大但激活小、可量化、可在消费级硬件跑、可被 Cursor/OpenClaw/llama.cpp/vLLM 二次开发。

② 西方优势在闭环后训练

长程工具使用、真实环境 RL、复杂 agent benchmark、自家产品用户数据回流、企业客户任务分布。Cursor Composer 把 Kimi K2.5 强基座，通过继续预训练 + 真实 session RL + 十万沙箱 + synthetic harder tasks + 错误工具调用的局部反馈，变成 coding agent。

③ 数据结构与生态位置不同

中国在中文表达/文档/OCR/国内场景天然贴近用户（豆包靠语音、视频、抖音集成、低门槛 UI 胜出，WIRED：超 DeepSeek 关键是 ByteDance 懂产品/分发/病毒传播）。但英文技术文档、GitHub issue、企业代码库、浏览器/IDE 操作轨迹更利于西方闭源通过产品闭环积累。

④ 芯片、监管与信任的外部变量

真实用户切换行为

社区是否出现持续、大规模「我取消 Claude，用 Qwen/Kimi/GLM/DeepSeek 完成真实工作」的帖子，而非 demo。

长程 agent 指标

Terminal-Bench 2、SWE-bench Pro、OSWorld-Verified、WebArena、BrowseComp，及私有企业 agent eval。

工具调用事故率

vLLM/llama.cpp/OpenCode/Cline/OpenClaw 中 tool_call parser、streaming、JSON、schema、compaction bug 是否明显下降。

上下文与记忆压缩

能否在 128K/256K/1M context 下保持稳定，不因 compaction 丢目录、丢目标、丢约束。

低比特量化保持能力

Q4/Q5/Q8 对 coding agent 的影响能否缩小（当前量化显著影响 tool calling 与 reasoning）。

被西方产品「隐形采用」

Cursor 基于 Kimi K2.5 极重要。更多 IDE/agent/客服/RAG 平台底层采用中国 checkpoint，说明实用价值被全球承认。

Ascend、寒武纪、摩尔线程、昆仑芯在大 MoE 推理/训练的稳定性、成本、工具链。只适合推理则前沿训练差距仍在。

视频模型音频与可控性

Kling/Seedance/Minimax 能否在原生音频、多镜头一致性、导演控制、长视频稳定性上追上 Veo/Runway。

09

审查与全球信任

能否提供可信海外部署、透明安全策略、可审计数据边界，及敏感/合规场景的可预测行为。

14最后的判断

2026 年中，中美之间已不是传统的「整体落后一代」，而进入「开放模型强势追平、闭源前沿与稳定 agent 仍落后、视频和 OCR 局部接近或领先」的阶段。

已追上

普通中文对话

已基本追上，在国内入口、语音、短视频、多功能消费应用上更贴近本土用户。

第一梯队

小模型 / 本地模型

Qwen/DeepSeek/Kimi/GLM 是开发者会主动选择的模型，不只是民族品牌叙事。

未稳定追平

复杂编程智能体

聪明度接近，稳定性、工具链、长程行为还差——大概率还需 1–2 年。

含金量高

多模态文档 / OCR

非常强，Qwen-VL 是开放模型中最有实用含金量的方向之一。

明显差距

GUI agent

尤其是持续状态管理和低错误率，仍有明显差距。

接近最快

视频生成

Kling/Seedance/Minimax/Vidu 已是全球竞争者；专业音画、长镜头、工作流可控性 Veo/Runway 仍领先。

追赶更慢

全球企业采用

技术之外，合规、数据、审查、地缘政治与产品生态，会让追赶更慢（2–4 年甚至更久）。
