公众号文章归档 · 方案选择与操作指南 / 核验日期 2026-10-14

方案研究 · Pro 优化版

公众号批量导出先选路线，再下载。

研究判断：截至 2026 年 10 月 14 日，所查公开来源不足以确认某个候选能在 macOS 上完整归档任意第三方公众号的历史正文与媒体；这不等于证明此类工具不存在。已有链接时，先验证正文批量保存；需要全历史时，先核对清单。

本页用途：选方案，安排小样本试验。已核对公开文档、源码、发行页和问题反馈；未安装下载器、未登录目标账号、未执行批量导出。工具说明、用户反馈与本页建议分别标注。
先选路线能力对照8 种方案与下载入口操作步骤完整性验收来源

01 / 先确定目标

自己的公众号

先验证后台文章清单

从“已发表”页面核对最早日期、分页和次条，再保存正文。这条路线尚未在目标账号现场验证。

已有文章链接

先试 wx-kit 的 URL 下载

从原始发行页选安装包。先处理 3–5 篇，检查全文和本地媒体，再处理链接文件。

只收未来更新

评估 wx-kit 或 WeRSS

先连续观察几天，并对照实际发布记录。增量流程不能填补此前历史缺口。

他人的号，且没有完整清单

先补链接，暂不承诺全量

少量缺失文章，可评估逐篇保存工具。不要因为安装包存在，就把它当作全历史下载方案。

04 / 方案与原始入口

按你手里的条件选方案

以上优先级是试用顺序，不是运行成功或可靠性排名；本报告未对候选工具进行运行验证。每张卡保留原始入口、适用条件和证据限制。

Mac 试用顺序：先评估无需本地 CA 信任的已有链接方案。本地 CA 信任指把工具使用的根证书加入系统信任。wx-kit 的未签名、未公证提示需单独评估；WxArticleSaver 在 Mac 上涉及本地证书与代理。安装方式与权限范围见项目说明。本页不把关闭系统防护或自动读取 Cookie 列为默认操作。Windows 厂商的“全历史”仍是宣传；决定安装或付费前，核对 Mac 运行条件、实际费用与数据处理方式，并要求目标账号、指定年份的导出样本。S3 S10 S14

先确定你能否登录目标账号后台。其他号的历史整理，优先尝试“链接清单 + 正文批量下载”，同时记录清单缺口。

01优先小样本试用

wx-kit

桌面应用 + CLI

适合把已有文章链接批量保存到本地，也能持续检查新文章。

环境 / 输出
macOS Apple Silicon / Intel、Windows；CLI 文档含 Linux
MD / HTML / PDF / 元数据；本地图片、视频按适配情况保存，在线播放链接不算本地媒体

试用步骤

登录与数据
未签名、未公证安装包需自行评估系统信任提示。按 URL 下载与登录订阅是两条流程；没有列表入口不等于正文不能下载。

06 / 可操作流程

我建议先这样试：清单与正文分开做

下面是建议流程。本次没有代你安装工具或执行抓取。若目标是自己的号，优先核对后台清单；若目标是其他号，历史页面、作者合集、已有收藏和公开搜索可以补链接，但不能自动证明完整。 自有后台路线是待验证的建议，不代表已确认账号适用资格，也不代表后台有一键导出按钮。

  1. 先定范围，并建立链接清单。

    写下账号、截止日期、最早需要的日期。清单每行记录标题、发布时间、原文链接、清单来源。把已删除、付费或无权访问项单独标记。去重后保留原始清单与时间范围。

  2. 从原始发行页下载候选工具，先处理 3–5 篇。

    优先评估 wx-kit 的已有 URL 下载流程。少量文章可先用浏览器保存页面作为对照，并断网检查正文和图片。选择早期、近期、多图和有媒体的文章，避免只试最新一篇。未签名应用的信任决定由你确认；本页不要求关闭系统防护。

    样本通过只支持继续批处理，不证明全历史覆盖。仅保留远程媒体链接不计为对应媒体已离线保存。测试样本应跨新旧日期，并包含次条、多图和所需音视频。

  3. 抽样通过后，分批下载并记录失败。

    已安装并确认 CLI 可用时，可以按项目文档使用链接文件模式。失败、登录过期或限流都要保留原因；不要把空文件当成功。不要以快速换账号的方式规避限制。

    链接文件 articles.txt：每行一条原文 URL

wx-kit download --urls-file articles.txt --formats md,html,meta

    WeRSS 另行记录正文抓取、页数上限和导出开关，避免把配置差异误判为能力差异。清单返回空、触发登录验证或频率限制时，记录失败并停止该批次，按项目允许的方式处理；不以换账号规避限制。S8

  4. 断网检查内容，再计算覆盖范围。

    核对正文末尾、图片相对路径、音视频、标题、时间和来源链接。对照清单检查成功数、失败数、缺媒体数。没有可信总清单时，只报告“保存了这些文章”，不要报告“公众号全部导完”。

如果只想保存未来文章

评估 wx-kit 或 WeRSS 的增量流程。先观察连续几天，并对照实际发文次数；最新一篇的回退机制可能漏掉两次检查之间发布的内容。增量启动成功不能解决此前历史缺口。

如果必须得到完整历史

自己的号先用后台逐页对账。其他号可以向作者取得文章目录或授权存档，也可以让服务商用指定账号、指定年份现场验收。拿不出完整清单时，不把“全量”作为交付承诺。

07 / 清单对账

核对已知清单，同时保留未知缺口

清单内完成率计算

先约定保存范围：正文、图片、音频和视频分别写清。只有所需内容都通过离线检查的文章，才计入验收通过篇数。数量按文章去重；本计算不联网、不保存数据。

请输入两个数量。

本结果只表示已知清单中约定内容的离线验收比例。100% 不能证明账号历史清单完整。

未发现的文章不会进入分母，因此不能证明历史穷尽。不得静默删除失败项以提高比例。应保留：清单来源、起止日期、失败项及原因、媒体缺失项；范围排除项需提前明确并另行记录。即使计算结果为 100%，也只说明已知清单内完成。

只要还有文章未确认通过验收，百分比最高显示 99.9%，并保留准确篇数。
