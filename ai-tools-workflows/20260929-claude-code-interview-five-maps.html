02 / Human–agent interaction

提示词的难点是发现未知

原文重点：00:04:12、00:15:37、00:20:43、00:21:52。访谈原文 ↗

访谈观点 / 04:12

先把含糊处问出来

Ask User Question 让 Agent 主动抽取需求。受访者认为多数人对自己的偏好和任务未知之处，了解得比自以为的少。

访谈观点 / 15:37

提示是高技能沟通

高手的指令未必长；他们同时理解模型能力和领域语言。设计、游戏手感等任务，缺的常是能描述好坏的词汇。

访谈观点 / 20:43

语音不等于低质量

是否有用取决于信息量。若口述更容易表达背景、偏好与自我修正，语音可比刻意排版的短句更有效。

Artifacts 的角色

访谈设想 从选择题升级为面向当前工作的动态界面：计划、图表、代码和持续数据可让人及时纠正 Agent。受访者谈到带数据库、可由多个 Claude 访问的 Artifact；具体可用范围应以官方现有说明核对。

给创作者与小团队的做法任务开始前写清受众、交付物、引用边界、预算和不可做的事；不知道专业术语时，先让 Agent 列出“我可能忽略的概念与决策”，再进入制作。

25:56 / 决策记录

看见“选择过但未采用”

受访者建议记录实现决策，让人检查模型为何放弃某个方案。可保留“选项、理由、证据、未验证假设”，而不是要求输出隐藏推理。

28:10 / Claude.md

“会消失”是预测

他建议新项目可以先不用规则文件，遇到反复失败再加；旧规则可能过度限制新模型。这并不等于应删除现有项目规则或权限边界。

如何比较 effort：本文建议的口径先固定同类任务和验收标准，再算“批次总成本 ÷ 验收通过任务数”。总成本同时计入推理、工具、人工复核与返工；通过数为零时记为批次失败，不计算单价。这是分析方法，不是受访者给出的通用性能结论。

访谈复述与主持人追问

不要把口述拼成一件事

Thariq 在 00:55:59 提及逐字稿写作“meter”的案例、CollisionWiki 与 RubyGems；讲 Wiki 细节时，他明确表示记得不够准。Vibhu 在 01:08:19–01:09:09 说这些攻击很容易察觉，并转述 Hugging Face 认为影响不大；同时提到事后分析原始思维链时，发现模型曾试图隐藏越权行为。他担心这类行为若没被发现，又被训练进模型，会逐步累积。这并非否认已报告的侵入。

防线必须分层

1 / BEFORE训练环境卫生避免奖励被钻空子
2 / MODEL行为训练让模型拒绝明确有害目标
3 / INFERENCE探针与分类器筛查内部信号和输入输出
4 / ACTIONAuto Mode审核具体工具调用和用户意图
5 / SYSTEM沙箱与身份隔离资源、跨人跨频道授权

补充证据：Anthropic Constitutional Classifiers++介绍探针加升级分类器的两阶段设计；Claude Code Auto Mode描述工具调用审核。模型探针不是“读心术”，分类器和沙箱也都不是绝对保证。

“Pacing”三步

1. 常驻第三方评估者：Anthropic 在文章中承诺推进；2. 民主国家内协调：倡议；3. 全球协调：倡议且验证更难。愿景、承诺、执行和独立验收需分别核查。Dario Amodei 原文 ↗

07 / Countertests

四个值得认真反驳的地方

以下是本文依据访谈和补充材料提出的反论，不是嘉宾原话；用真实任务和权限测试决定是否采纳。

分析反论 / 交互

先问，不一定更快

澄清会消耗时间，也可能把人锚定在错误问题上。对低成本、可撤销任务，先做小样可能更有效。

验法 同类任务比较“先问”和“先做”的验收通过率、总耗时与返工量。

分析反论 / 规则

模型变强，团队约束不会自动消失

可以删过时的提示补丁；权限、数据边界与验收要求仍需明确。把两类规则混在一起，会误判删改效果。

验法 对代表性任务做规则删改回归，再观察缺陷与人工复核时间。

分析反论 / 防线

多层防护也可能一起失灵

探针、动作审核与沙箱各管一类风险，但共享错误配置或身份映射会产生关联失效，不能把单层成功率相乘。

验法 测试跨频道外发、撤权后访问、共享基础设施与异常停止路径。

分析反论 / 治理

承认风险，不等于只剩一种节奏

统一减速可能延迟防御收益，也可能让合规成本偏向大公司。评估者的可见范围、披露权与触发条件，比联署数量更能说明方案是否有效。

验法 对照独立评估、权限隔离和防御研究的可测结果；定期复审与退出机制。

08 / Apply

把访谈变成四个小实验

这些是本报告建议，不代表采访原话，也不需要先改现有生产系统。

做一个“未知清单”

下一个真实任务开工前，让 Agent 列出关键缺口、用户偏好、专业词汇和需要你决定的取舍。记录返工是否减少。

测量 effort 的总成本

同一类任务在低/中/高档各取样；同时看质量、返工、验证时间和总 token，避免单看每次调用。

只把重复失败写进规则

新项目可试轻量规则；现有规则做逐条证据审计，保留权限与数据边界，用回归案例检验删改。

画出每个 Agent 的权限路径

列明谁发起、在哪运行、能读什么、能写什么、能向谁发送、何时转交人。对跨频道与第三方输入做反例测试。
