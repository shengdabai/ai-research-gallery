03 — Design Philosophy

三层架构 哲学

▮

Layer 1

Dumb Pipeline

管道保持确定性，事件路由与任务编排完全可预测。可审计、可回放、可调试——企业采用 AI 的前提。

★

Smart Step

策略是唯一治理检查点。声明式 YAML 配置写回权限：评论、标签、状态检查、提交建议分别授权。

04 — Architecture Innovation

架构 创新

Innovation 01

单航班执行 + 429 背压

拒绝并发而非排队缓冲。对昂贵的 LLM 操作，背压把调度权还给上游，避免资源过载和成本失控。反直觉但极其务实。

Innovation 02

Clone-on-Write 注册表

借鉴数据库 MVCC 的不可变快照机制，内存 Map 副本+SQLite 事务，确保任务执行期间 Worker 配置不会被热更改。

Innovation 03

Policy-as-Code 治理

将 AI 输出通过声明式策略过滤写回，所有审批和拒绝生成审计条目。比 prompt engineering 可靠得多，是 AI 进生产的必经之路。

Innovation 04

三层 Worker 统一模型

Managed（Docker 容器）、Adapter（Ollama/vLLM 桥接）、Unmanaged（外部 HTTP）——一套 YAML 配置统一云端与本地模型接入。

Innovation 05

密钥前缀自动注入

通过前缀检测（如 sk-ant-oat01-）自动注入正确的环境变量，消除大量样板配置。小设计，大体验。

Innovation 06

MCP Server 集成

内置 MCP 服务器支持，标准化工具链访问，让 Agent 能无缝调用现有 DevOps 工具库，降低集成成本。

07 — Transferable Design Principles

可迁移 设计原则

治理与智能分离

Consensus: 5/5 advisors

任何让 AI 代理执行有副作用操作的产品，都需要一个独立于 AI 本身的策略层。不要把治理逻辑混入 prompt，而是建立独立的 Policy Gate。

Policy-as-Code

Consensus: 4/5 advisors

将 AI 的输出通过预设的治理逻辑过滤，是所有 AI 代理进入生产环境的必经之路。声明式配置比 prompt engineering 可靠得多。

应用: 用 YAML/JSON 定义 AI 的写回权限边界，替代在 system prompt 中用自然语言描述限制。

隔离不确定性边界

Consensus: 4/5 advisors

LLM 只在定义好的 Step 边界内工作，其他层保持确定性。这让整个系统可审计、可调试、可回放。

应用: 将 AI 推理封装为独立的函数/服务，输入输出有明确 schema，外部流程保持确定性编排。

声明式能力定义

Consensus: 3/5 advisors

用 YAML 声明 AI 代理的能力边界（可用工具、资源限制、超时时间），而非在代码中硬编码。这应成为行业标准模式。

应用: 为每个 AI Worker 创建配置文件，声明可调用工具、内存限制、最大执行时间、输出格式。

背压优于排队

Consensus: 3/5 advisors

对昂贵的 AI 操作，拒绝（429）比缓冲更安全。背压把调度权还给上游，避免 token 成本失控和资源过载。

应用: 在 AI API 网关中实现基于成本的速率限制，超载时返回 429 而非无限排队。
08 — AI Work Paradigm Shift

AI 工作 新范式启发

从 mecha.im 的设计中提炼出的 AI 时代工作方法论转变。
这不只是一个产品分析——它揭示了 AI 协作的底层逻辑。

Paradigm 01

从"提示工程"到"治理工程"

Before: "请不要修改 main 分支"
After: policy.commit.branches.blocked: [main]
Paradigm 02

从"单模型依赖"到"模型可替换"

mecha.im 用一行 YAML 切换模型的设计揭示了一个趋势：AI 产品不应该绑定单一模型。设计时将模型视为可替换的"Worker"，用统一接口抽象，让产品的价值锚定在编排和治理层。

model: claude-sonnet-4-6 → model: gemini-2.5-pro
一行配置，零代码改动
Paradigm 03

从"云端托管"到"主权 AI"

单二进制自托管不是技术选择，是信任模型的选择。企业对 AI 代理最大的恐惧是"代码泄露到别人的服务器"。自托管 + 策略控制的组合，是打开企业市场的金钥匙。

Your code never leaves your infrastructure.
Policy decides, not the cloud.
Paradigm 04

从"智能堆砌"到"确定性优先"

大多数 AI 产品把"更智能"当卖点。mecha.im 告诉我们：企业买单的不是智能，而是可控性。把确定性做到极致（可审计、可回放、可调试），智能只需要放在该放的地方。

Deterministic pipeline + Isolated intelligence
= Enterprise-ready AI
Paradigm 05

从"功能竞赛"到"架构品味"

20 stars 的产品凭什么值得五模型议会分析？因为架构品味。在 AI 工具同质化严重的今天，优雅的抽象、正确的分层、克制的设计比堆砌功能更有长期价值。

"dumb pipeline, smart step, policy gate"
九个词定义了一个品类
Paradigm 06

从"一次性交互"到"事件驱动"

AI 不应该只在你打开 IDE 时工作。事件驱动的 AI（webhook 触发、自动响应、策略过滤）才是 AI 价值最大化的方式。让 AI 成为基础设施的一部分，而非工具箱中的一个按钮。

PR opened → auto review → policy filter → write back
Human: sleep. AI: work.

思维 转变

Old Paradigm

  • AI 是聊天工具，需要人工触发
  • Prompt 是唯一的控制手段
  • 追求"最强模型"解决一切
  • AI 输出直接进生产
  • 功能越多越好
  • 托管 SaaS 是默认选项
→

New Paradigm

  • AI 是事件驱动的基础设施
  • 声明式策略层控制 AI 行为边界
  • 模型可替换，价值在编排和治理
  • Policy Gate 过滤后才能写回
  • 架构品味 > 功能数量
  • 自托管 + 主权控制是企业刚需
09 — Strategic Roadmap

发展 路线图

Phase 1 — 0-6 Months

场景深耕

聚焦 PR Review + Issue Triage 两个核心场景，打造开箱即用的完整体验。提供丰富的 Worker 模板和 Quick Start 文档。

Phase 2 — 6-12 Months

DX 与生态

投资开发者体验：--dry-run 模式、Policy 决策结构化日志、YAML JSON Schema + IDE 补全。建立 Worker/Policy 社区注册表，参考 Terraform Provider 模型。增强可视化 Web UI。

Phase 3 — 12-18 Months

企业化与扩展

Open Core 商业模式：企业版叠加审计日志、RBAC、合规报告、多租户隔离。从 SQLite 迁移到可扩展存储，支持 DAG 编排。抢在 GitHub 原生集成之前建立护城河。

Phase 4 — 18+ Months

平台化

成为 AI Agent 领域的"容器编排器"。多节点协同、分布式调度、跨仓库工作流。从 DevOps 扩展到更广泛的事件驱动 AI 自动化场景。
