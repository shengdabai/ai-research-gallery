04 · AI 专题

AI 的真正分界线，
不是桌面长什么样

同一系统中，集成显卡与高端独显的差距可能远大于系统差距。先看任务，再看加速后端，最后看操作系统。

M
APPLE SILICON

Metal / MLX

统一内存、低功耗与原生工具让本地推理和原型体验顺滑。

  • MLX：CPU / GPU 共享内存模型
  • PyTorch MPS：通过 Metal 加速
  • 限制：不支持 NVIDIA CUDA
W
WINDOWS + WSL

CUDA / DirectML

NVIDIA 独显可在 WSL 使用 CUDA；DirectML 覆盖 DirectX 12 GPU。

  • 保留 Windows 软件与游戏
  • WSL 运行 Linux 工具与容器
  • 限制：双环境需要纪律
L
NATIVE LINUX

CUDA / ROCm

研究、训练、推理服务和云 GPU 的共同基线。

  • CUDA / NCCL / 容器路径成熟
  • 最接近生产与集群环境
  • 限制：硬件兼容需先核对
工作负载判断

瓶颈通常是“能否装下”，其次才是速度

量化权重、KV Cache、运行时与系统都要占内存。macOS 的统一内存可让 GPU 使用较大的共享内存池；独显受显存容量约束，但高端 NVIDIA GPU 往往拥有更成熟、更快的 CUDA 路径。

低摩擦：macOS｜高峰值与扩展：Linux / Windows + NVIDIA

05 · 为什么常推荐 macOS / Linux

相似的表面，
不同的胜因

两者都有成熟的 shell、SSH、脚本与开源工具链；macOS 胜在“整合”，Linux 胜在“原生生产环境与可控性”。

A

为什么选 Mac

把 AI 工作台做成消费电子

  • 统一内存：CPU 与 GPU 共享内存池。
  • 低摩擦：驱动、硬件、续航由同一厂商整合。
  • 双重身份：成熟桌面 + UNIX 命令行。
  • 原生生态：MLX、Metal、Core ML。
反证：必须依赖 CUDA 扩展、多 NVIDIA GPU 或 Linux-only 驱动时，Mac 不是合适主机。
B

为什么选 Linux

让开发环境贴近算力与生产

  • CUDA 主场：框架、驱动、容器与集群成熟。
  • 可复现：开发容器到云 GPU 差异最小。
  • 可控制：服务、权限、内核均可配置。
  • 远程优先：SSH、调度与监控是一等工作流。
反证：只用云 AI、依赖特定桌面软件或重视游戏时，Linux 的维护成本可能高于收益。
别忽视

Windows 不是“不适合 AI”

带 NVIDIA GPU 的 Windows 工作站通过 WSL 2 可以运行 Linux 工具、容器与 CUDA 应用；如果还需要游戏、企业软件或特定硬件，它往往是最合理的一机多用方案。

误区清单

最后拆掉 6 个偏见

系统选型最危险的不是知识少，而是把局部经验当成普遍规律。

“Mac 做 AI 一定最快”＋

错。它在本地推理的能效、容量与易用性上突出，但 CUDA 训练与多 GPU 不是强项。

“Linux 就是一个系统版本”＋

不准确。Linux 是内核；Ubuntu、Fedora、Debian 等发行版才是完整系统。

“Windows 没法做 Linux AI”＋

过时。WSL 2 能运行 Linux 工具、容器和受支持的 CUDA 工作负载。

“UNIX 与 Linux 是一回事”＋

不是。UNIX® 涉及规范与认证；Linux 是类 UNIX 内核。

“显存越大，模型一定越快”＋

不一定。容量决定能否装下；速度还受带宽、算力、量化和内核优化影响。

“换系统就能提高 AI 效率”＋

未必。若主要使用云模型，流程自动化通常比换系统更重要。

08 · 底层原理

九个概念，建立真正的系统脑图

输入关键词过滤卡片。每张卡都回答：它是什么、为什么重要、如何观察。

9 / 9
内核与系统调用 Kernel / syscall

内核拥有最高权限，调度 CPU、内存和设备。应用通过系统调用请求打开文件、创建进程或访问网络，而不是直接碰硬件。

应用 → API / runtime → syscall → 内核 → 驱动
进程与线程 Process / thread

进程是资源与隔离边界，线程是其中的执行流。AI 数据加载、Web 服务并发和图形界面卡顿，都与调度有关。

观察：ps / tasklist / Get-Process
虚拟内存与交换 VM / swap

每个进程看到独立地址空间；物理内存紧张时系统可能压缩或换页。模型“能加载”不等于能高效运行，频繁换页会让速度骤降。

容量决定能否装下，带宽与算子决定速度
文件系统与路径 APFS / NTFS / ext4

文件系统决定权限、大小写、快照与元数据。Windows 与 WSL 混用工程目录时，路径语义和 I/O 性能尤其容易踩坑。

/Users / C:\Users / /home
用户、权限与沙盒 UID / ACL / sandbox

最小权限降低恶意脚本和供应链攻击的破坏面。不要为省事长期以管理员或 root 身份跑包管理器和 AI 工具。

原则：普通用户运行，按需临时提权
驱动、运行时与 API Driver / runtime

GPU 必须经驱动和计算运行时暴露给框架。CUDA、Metal、ROCm、DirectML 不是模型，而是不同加速路径的一部分。

GPU → driver → runtime → framework
服务与守护进程 Service / daemon

后台服务负责网络、日志、更新与模型服务。桌面系统偏图形化管理，Linux 服务器常以 systemd 管理。

观察：launchctl / sc.exe / systemctl
包与依赖锁定 Package / lockfile

系统包、语言包和容器镜像是三层不同依赖。锁定版本并记录架构，才能让 AI 项目可靠迁移。

源码 + lockfile + 环境说明 + 模型版本
x86-64 与 ARM64 Architecture

指令集不同会影响二进制、容器镜像和 Python wheel。Apple silicon 是 ARM64；多数 NVIDIA 训练工作站仍是 x86-64。

uname -m / echo %PROCESSOR_ARCHITECTURE%

09 · AI 硬件

CPU、GPU、NPU 和内存各做什么

AI 体验不是单看 TOPS 或显存数字。容量、带宽、算子支持、功耗和软件栈共同决定结果。

CPU

通用控制

负责系统、预处理、调度和未加速算子；核心多不代表模型一定快。

GPU

主力矩阵计算

训练与高吞吐推理的主力。NVIDIA 走 CUDA，Apple 走 Metal，AMD 常走 ROCm。

NPU

低功耗专用推理

适合摄像头、语音和系统级后台模型。重负载本地 LLM 开发通常仍主要依赖 GPU；实际可用性取决于运行时和应用。

MEMORY

容量 + 带宽

统一内存可给 CPU/GPU 共用较大池；独显 VRAM 带宽优秀但容量固定。KV Cache 随上下文与并发增长。

采购时看四件事

容量决定能否装下，带宽影响生成速度，生态决定算子能否跑，散热与功耗决定能否持续跑。不要用单一跑分代替真实模型验证。

10 · 虚拟化

原生、容器、虚拟机与 WSL 2

它们解决的问题不同：环境隔离不等于硬件虚拟化，能运行也不等于零损耗。

原生运行

最短硬件路径

直接使用宿主驱动与文件系统。排错简单，但环境容易被项目依赖污染。

Docker / Podman 容器

共享宿主内核

封装用户态依赖，启动快、适合交付；Linux 容器在 macOS/Windows 上仍需轻量虚拟机。

虚拟机

完整客体系统

隔离强，可运行不同内核；资源开销更大，GPU 直通和驱动兼容要单独验证。

WSL 2

Windows 内的 Linux VM

兼顾 Windows 软件与 Linux 工具。项目放在 Linux 文件系统内，避免跨 /mnt/c 的高频小文件 I/O。

记忆法：容器打包应用环境，虚拟机承载完整系统，WSL 2 是微软深度整合的 Linux 虚拟机工作流。

12 · 安全与隐私

安全不是某个开关，而是多层边界

操作系统负责身份、权限、代码签名、磁盘加密和沙盒；AI 工具还会引入模型、插件、依赖与数据去向风险。

macOS

Gatekeeper · SIP · FileVault

验证应用来源、保护关键系统区域、加密磁盘。终端和自动化工具仍应按最小权限运行。

Windows

Defender · SmartScreen · UAC

恶意软件防护、下载信誉检查与管理员确认；BitLocker 负责磁盘加密。

Linux

sudo · SELinux / AppArmor · LUKS

权限透明且可细分，但安全基线需要主动维护；服务器还需更新、端口、密钥和日志策略。

本地模型

数据可留在设备

仍要检查客户端遥测、模型许可证、插件和索引目录；“本地运行”不自动等于完全离线。

云端 AI

数据离开设备边界

先确认服务条款、保留期、训练用途、地区与企业策略，再上传客户资料、代码或个人信息。

GGUF 常用于 llama.cpp 跨平台量化推理；GPTQ / AWQ 常见于 GPU 量化路径；safetensors 是安全高效的张量封装。最终兼容性由模型架构、量化方法、后端和算子共同决定。

14 · 成本模型

不要只比较机器售价

总拥有成本 TCO = 采购 + 云资源 + 软件 + 电费 + 维护时间 + 迁移与锁定风险。

CAPEX

一次性采购

Mac 要一次选对内存；Windows/Linux 工作站常可升级显卡、内存和磁盘。

OPEX

持续算力

云 GPU 适合突发训练；长期高利用率可能自有设备更划算，但还要计算电力、散热与闲置。

TIME

维护时间

安装、驱动、环境冲突和排错都是成本。Mac 通常省本地维护，Linux 通常省生产迁移。

LOCK-IN

迁移与锁定

平台专属 API 能带来体验，也会提高迁移成本。优先保留标准模型格式、容器与可复现配置。

决策公式：若 80% 任务在浏览器或云端，优先熟悉度；若 80% 是本地推理，优先内存与带宽；若 80% 是 CUDA/部署，优先 Linux 兼容与 NVIDIA 生态。
