第一级 · 受控写作

ASD-STE100：航空维修手册里练出来的写作规范

ASD-STE100（Simplified Technical English，简化技术英语）是一种受控自然语言：它限制你能用哪些词、每个词只能有哪种含义、句子能写多长。它在 1980 年代应欧洲航空公司的要求，由欧洲航空航天工业协会（AECMA）开发，目的是让母语不是英语的机务人员不误读维修手册。A

当前版本是 Issue 9（2025-01-15）：53 条写作规则 + 约 900 个批准词，每个批准词只有一个词性、一个含义；另列约 1,200 个"不批准词"及替换建议。规范由 ASD 下属的 STEMG 维护，可免费申请，名称是注册商标（EUTM 017966390）。A C

Issue 9 的副标题改成了"Standard for Technical Documentation"，从"规范"升级为国际标准，现已用于国防、铁路和其他工业领域。

硬性上限（规则第 4–6 节）

另有软性要求：同一个东西始终用同一个词；不省略 the / a / this；程序用主动语态和祈使句；复杂内容用竖排列表；一段只讲一个主题。

证据：受控语言真的更好懂吗？

Boeing × 华盛顿大学（1995）A

Shubert 等人对比 SE 与非 SE 的飞机维修程序：SE 显著提高了复杂文档的理解度和信息定位能力；简单文档上差异不显著；阅读速度没有变快。非母语读者受益看起来最大，但样本量不均衡，没做统计检验。

175 名一线机务（1996）A

Chervak、Drury、Ouellette 用 16 张工卡（难/易 × SE/非 SE × 两种版式）测试：SE 显著提高理解，难工卡和非母语技师受益最大。这补上了 1995 年研究缺的统计结论。

LLM 时代的新数据C

开源 skill 作者用正则 linter 测 6 个 Claude 模型 × 8 个任务（96 次生成），称开启 STE skill 后"每百词违规数降 72.9%"，输出 token 也全面下降。注意：这只测了规则遵从度，没测人类理解度，而且是作者自测。

证据边界：STE 的收益集中在"复杂内容 + 非母语读者"。对已经很顺的短文，它可能只是让文字变干。Karpathy 说的"80%"恰好对应这个结论：保留短句、一词一义、主动语态这些高收益规则，放宽词表这种高成本规则。

动手试：80% STE 粗检器

粘贴一段英文，实时检查：句长（程序句 20 / 描述句 25）、常见不批准词、被动语态、进行时 / 完成时、名词串。只覆盖少数高频规则的启发式，不能代替官方认证。

    第二级 · 图示

    为什么一张图有时顶一万个字

    认知科学对这件事研究了近四十年。Larkin 与 Simon 1987 年的经典论文《Why a Diagram is (Sometimes) Worth Ten Thousand Words》A给出了机制：两种表示即使包含相同的信息，处理成本也可能差很多。文字是顺序排列的命题，图按平面位置索引。

    图的优势落在三个环节：

    • 搜索：一起用到的信息在图上挨在一起（位置索引），不用来回翻找。
    • 识别：文字里隐含、要靠推算的关系，在图上直接可见。
    • 推理：可以用知觉直接做推断，比如一眼看出谁连着谁、谁比谁大。

    后续研究（Cheng，2004）在滑轮问题上测到：图示解法最多比等价文字容易 6 倍；而且表格并不总比文字好，说明图的优势不只是"把东西排整齐"。A

    多媒体学习：图文 vs 纯文字

    Mayer 多媒体原则的效应量（Cohen's d，迁移测试）。d > 0.4 通常视为有教育意义。

    来源：Mayer 2021（13 项实验，13/13 为正）；Mayer 2017（5 项）；Fletcher & Tobias 2005（50+ 比较，二手转述）。Mayer 的中位数主要来自其本人实验室，跨实验室汇总的效应通常更小。

    标题里的"有时"很重要：图的优势有条件。它擅长表达结构、关系、流程和空间信息。遇到精确的论证链、例外条件、法律式限定，文字往往更好。LLM 画图还有一个特有风险：图会把不确定的关系画成确定的箭头。所以 Karpathy 的"图比字好"应读作"结构性内容用图更好"。

    让模型画好图的实用要点

    选能被渲染的格式

    Mermaid、Graphviz、PlantUML、内联 SVG：文本即图，能 diff、能改、能版本化。图像模型适合信息图，但文字容易出错，也不好修改。

    先定图的类型

    时序 → 时序图；状态 → 状态机；层级 → 树；对比 → 矩阵；因果 → 有向图。在提示里说清楚类型，比说"画张图"可靠得多。

    要求标出不确定性

    让模型用虚线表示推测关系、实线表示已证实关系，并在图下列出它做的假设，抵消"图让一切看起来很确定"的副作用。

    第三级 · 交互网页

    "用 HTML 输出"：Google 用大样本实验做了验证

    2025 年 11 月 Google Research 发表《Generative UI: LLMs are Effective UI Generators》A：让模型针对每个提示即时生成定制网页，再与四种形式做人类成对偏好评测。提示词随机取自 LMArena。

    结果：不计生成时间时，评审者82.8% 的情况下更偏好生成式 UI，而不是标准 Markdown 回答；信息检索类问题上升到 90.5%。生成页面仍不如人类专家做的网站，但有 44% 的情况"至少相当"。作者认为这是新模型才涌现的能力。

    同一能力已经产品化：Gemini App 的动态视图、Google 搜索 AI 模式、Claude 的 Artifacts，以及 Karpathy 在 2025 年度回顾里说的 "LLM GUI"。他当时就说：聊天文字像 1980 年代的命令行，人更喜欢视觉化、空间化的信息。C

    五种回答形式的 Elo 得分

    LMArena 抽样提示，成对人类评审。Elo 越高表示越常被偏好。来源：Leviathan 等，arXiv 2604.09577。

    这个实验的关键前提：评审时不计生成速度。Markdown 回答几秒就出来，一个交互页可能要几十秒到几分钟。所以结论应读作"值得等待时，HTML 更好"，而不是"任何时候都该用 HTML"。

    HTML 好在哪：比图多出的三样东西

    可操作

    滑块、切换、筛选。读者能自己拨参数看结果变化，这是"主动学习"，比被动阅读记得牢。本页的 STE 粗检器就是例子。

    分层披露

    先给结论，细节折叠，原文可切换。同一页同时照顾想扫一眼的人和想深挖的人，这是线性文字和视频都很难做到的。

    可携带、可存档

    单文件自包含，离线能开，可以搜索，可以转发。它比视频更容易被检索和引用，这是 HTML 相对第四级的隐藏优势。

    第四级 · 讲解视频

    "3b1b 风格"：模型写动画代码，而不是生成像素

    3Blue1Brown 的 Grant Sanderson 用自己开发的 Python 库 Manim 做数学动画。"3b1b 风格视频"在工程上就是：LLM 写 Manim 脚本 → 渲染成矢量动画 → TTS 配音 → 合成。2025 年起有一批论文专门研究这条路线。

    规划主题拆成分镜：每幕讲什么，配什么图形
    写代码每幕生成 Manim / Remotion 代码
    渲染本地跑代码出画面，报错就回到写代码重试
    视觉审稿VLM 看渲染帧，查重叠、出界、错位
    配音ElevenLabs 或本地 TTS（Kokoro / Chatterbox）
    合成ffmpeg 对齐音画，输出 mp4

    TheoremExplainAgent（ACL 2025）A

    240 个 STEM 定理，生成 5 分钟以上的 Manim 讲解视频。o3-mini 智能体成功率 93.8%，综合分 0.77，和人工 Manim 视频的综合分持平。但元素布局是最弱项，失败大多来自模型编造不存在的 Manim API；不允许重试时成功率很低，允许 5 次重试可达约 90%。

    人工制作视频 vs 智能体生成（GPT-4o 版布局分 0.59 → Code2Video 改进到 0.91）。

    Code2Video（2025）A

    规划器 + 编码器 + 审稿器三段式，用"视觉锚点"让 VLM 修布局。相对直接生成代码提升约 40%，并且优于像素级视频生成模型。它还提出 TeachQuiz 指标：先让 VLM"遗忘"一个概念，看完视频后再测能恢复多少。这是在测"看完学会了没"，而不只是"好不好看"。

    风险一：流畅性错觉

    心理学的"加工流畅性"研究表明，越容易处理的信息越容易被当成真的。精美的动画和网页提高的是"感觉懂了"，不一定是"真的对"。Karpathy 自己 2023 年说过：LLM 本质上就是"做梦机器"。越往上爬，越需要配套的核查手段。

    风险二：理解外包

    原帖的前提是"人的工作上移到监督"。可如果连"理解"都交给模型做的讲解材料，监督者看到的就是模型选择给你看的那一面。可行的对策：让讲解附带可追溯的来源和可运行的验证，例如 explain-ladder 给每种格式配机器检查。

    风险三：证据不均

    第一、二级有几十年实证，第三级有一次严肃的大样本偏好实验，第四级目前主要是能力演示和自动化指标。原帖本身没有引用任何研究，也没给成本数字。

    修正后的用法

    按内容选级别，而不是一律爬到顶：规则、限定用受控文字；结构、关系用图；要自己探索的数据和参数用 HTML；直觉性的连续变化（几何、动态过程、算法执行）才值得做视频。

    落地

    一、给 AI 汇报加一条"80% STE"文风规则

    在 Claude Code / Codex 的汇报约定里加一行 "Write reports 80% of the way to ASD-STE100"；中文汇报用对应的简明中文规则：一句一个动作、主动语态、同一事物同一叫法、单句不超过 35 字、少用"进行了 / 实现了"等虚化动词。成本：一行配置，可以 A/B 一周看效果。

    "简明中文规则"是本页参照 STE 自拟的，中文没有对应的官方标准D。

    二、对外汉语教学：受控中文就是 STE 的原始场景

    STE 的实证结论是"非母语读者 + 复杂内容受益最大"，这正是外国学员读中文讲解的处境。可以给教材和课程讲解定一份"受控中文"词表：按 HSK 等级限词、一词一义、句长上限，再让 LLM 按这份规范改写例句和讲解。这是有研究支撑、而且同行少有人做的方向。

    三、HTML 报告补一层"可审计"

    四、用一节课验证第四级

    挑一个"有连续变化"的知识点（例如声调曲线、汉字笔顺、部件组合），做 1–3 分钟的 Manim 动画 + 本地 TTS 旁白试片（中文旁白先比较本地 VoxCPM 和 Kokoro 的中文质量）。用"学员看前 / 看后小测"代替"好不好看"来评估，借用 Code2Video 的 TeachQuiz 思路。

    可复制的提示词

    第一级 · 受控写作
    Explain [topic] 80% of the way to ASD-STE100: one instruction per sentence, max 20 words for procedures and 25 for descriptions, active voice, one word = one meaning, no noun clusters longer than 3 words.
    第二级 · 图示
    Explain [topic] as a single Mermaid [flowchart/sequence/state] diagram. Use solid arrows for facts you are sure of and dashed arrows for assumptions. Under the diagram, list every assumption in one line each.
    第三级 · HTML
    Create a single self-contained HTML file that explains [topic]. Put the conclusion first and collapse the details. Add one interactive control that lets me change [parameter] and see the effect. Label every number with its source. No external resources.
    第四级 · 视频
    Create a 3b1b-style explainer video on [topic], about 2 minutes. Plan a storyboard of 4–6 scenes first, then write Manim Community code per scene, render it, check each frame for overlaps, and fix the layout. Use a local TTS (Kokoro or similar) for narration and merge with ffmpeg. Show me the storyboard before rendering.
